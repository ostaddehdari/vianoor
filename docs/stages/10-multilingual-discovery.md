# مرحلهٔ ۱۰ — چندزبانه، جستجو و تطبیق

محدودهٔ مصوب در [10-scope.md](10-scope.md)، تصمیم‌های مالکیت و مهاجرت در [10-data-model.md](10-data-model.md) ثبت شده‌اند. شاخه `stage/10-multilingual-discovery` و نسخهٔ رابط `V10.0.0` است.

## امکانات و مسیرها

- صفحهٔ `/{language}/experts`: جستجو با موضوع، زبان جلسه و زمان محلی؛ نمایش مجدد ظرفیت از مالک زمان‌بندی. انتخاب زمان هنوز رزرو نیست؛ رزرو مرحلهٔ ۹ ظرفیت را اتمیک نگه می‌دارد.
- مدیر: `/{language}/admin/localization` برای زبان‌ها، پوشش ترجمه، متن‌های ناقص، ویرایش متن انگلیسی، بازبینی/انتشار، تخصص‌ها و فرهنگ جستجو.
- صفحهٔ حرفه‌ای استاد: «ترجمه پروفایل و خدمات». استاد پیش‌نویس می‌نویسد؛ مجوز `translation.review` انتشار را کنترل می‌کند.
- فهرست ۱۴۷ زبان اولیه، قابل مدیریت در دیتابیس؛ AI و speech پیش‌فرض خاموش. فهرست زبان‌ها با زبان مکالمهٔ استاد همسان‌سازی شناسه دارد.
- ۹۹۵ کلید اولیهٔ رابط/صفحات در دیتابیس. فایل seed فقط مهاجرت اولیه است؛ اجرای مجدد تغییر مدیر را بازنویسی نمی‌کند. نبود ترجمه به انگلیسی برمی‌گردد. ترجمهٔ کامل ۱۴۷ زبان انجام نشده است.
- اطلاعات قدیمی غیرانگلیسی حفظ شده و `und` نشان‌دهندهٔ زبان نامشخص است؛ انگلیسی برچسب‌زدن به متن فارسی انجام نمی‌شود.

## API و مالکیت

تمام مسیرها زیر `/api/v2` هستند و از gateway/BFF موجود عبور می‌کنند:

| مسیر                                                                                      | مالک     |
| ----------------------------------------------------------------------------------------- | -------- |
| `languages`, `languages/:code`                                                            | taxonomy |
| `localization/bundle`, `translation`, `keys`, `coverage`, `review`, `jobs`, `specialties` | taxonomy |
| `experts/translations`, `experts/translations/review`                                     | scholar  |
| `profiles/language`                                                                       | profile  |
| `search/experts`, `search/synonyms`, `search/status`, `search/rebuild`                    | search   |
| `matching/expert`                                                                         | matching |

اسناد کارشناسان، تلفن و اطلاعات خصوصی وارد projection نمی‌شوند. هر نتیجه—even از Redis—از scholar دوباره دریافت می‌شود تا وضعیت حساب، انتشار، تخصص و اعتبار فعلی بررسی شود. تغییر متن اصلی ترجمهٔ قدیمی را از نمایش خارج می‌کند. ویرایش ترجمه تا انتشار جایگزین، مقدار منتشرشدهٔ قبلی را حفظ می‌کند.

## جستجو و رویداد

هر زبان فعال فیلد مستقل در نمایه دارد. زبان‌های دارای تحلیلگر داخلی OpenSearch از تحلیلگر اختصاصی استفاده می‌کنند؛ زبان‌های دیگر تحلیلگر Unicode استاندارد دارند. ادعای ریشه‌یابی اختصاصی برای تمام ۱۴۷ زبان وجود ندارد. فارسی/عربی نرمال‌سازی می‌شوند و تحلیلگر انگلیسی stemming دارد. ارتباط مفهومی از ترجمه، تخصص و واژه‌نامهٔ تأییدشده می‌آید، نه مدل AI.

تغییر ردیف در مالک داده، رویداد ابطال بدون متن شخصی را در outbox همان تراکنش ثبت می‌کند. مصرف JetStream با inbox و acknowledgment پس از commit است. بازسازی دسته‌ای تا ۳۰۰۰ استاد، نمایهٔ تازه می‌سازد و alias را اتمیک عوض می‌کند. Redis فقط شناسه‌ها را برای ۳۰ ثانیه نگه می‌دارد. نمایه منبع حقیقت نیست. `SEARCH_INDEX_PREFIX` محیط پذیرش را از نمایهٔ دمو جدا می‌کند.

## نصب روی سرور دمو

مسیر: `/opt/vianoor-stage10`؛ Compose همان `vianoor-stage4` و داده‌های مراحل قبلی است. تغییرهای schema افزایشی هستند. نسخهٔ قبلی در `/opt/vianoor-stage09` و backup خصوصی در `/root/vianoor-backups/stage10-*` باقی می‌مانند.

تصویر رسمی OpenSearch 2.19.6 روی CPU این VPS به علت glibc/x86-64-v2 اجرا نشد. توزیع همان نسخه و JDK همراه آن به `/opt/vianoor-opensearch-runtime` استخراج شد و با پایهٔ Debian موجود، کاربر 1000 و volume مستقل اجرا می‌شود. هیچ درگاه OpenSearch روی میزبان منتشر نشده است. تنظیم watermarks بر حسب فضای آزاد و مناسب دیسک فعلی دموست؛ افزایش حجم داده نیازمند تأمین فضای دیسک است.

پس از ساخت تصاویر `vianoor-services:stage10` و `vianoor-web:stage10`، `bash scripts/deploy/stage10.sh` پیکربندی، bootstrap، readiness و نسخهٔ نصب‌شده را کنترل می‌کند. برای این VPS متغیر `OPENSEARCH_BASELINE_RUNTIME` مسیر runtime سازگار را معرفی می‌کند. راه‌اندازی volume نیازمند مالکیت 1000:1000 است. کامپایل باید در کانتینر ساخت انجام شود، نه سرویس محدود به 256 MB.

## شواهد آزمون

آزمون نهایی روی سرور دمو در ۲۰۲۶-۰۹-۲۷ انجام شد:

- `npm run check`: موفق؛ معماری ۳۲ سرویس و ۱۲۲ نیازمندی، lint، ۴۸ آزمون، build سرویس‌ها و هر دو برنامه و typecheck.
- `npm run smoke`: موفق؛ smoke پایهٔ ۳۲ سرویس و مسیرهای فارسی/انگلیسی هر دو برنامه. پاسخ readiness=503 در حالت scaffold این smoke، اثبات اتصال واقعی نیست.
- `tests/integration/discovery.test.ts`: موفق با PostgreSQL، OpenSearch، NATS و Redis واقعی روی همان VPS؛ ۱۴۷ زبان، fallback، گردش انتشار و ابطال ترجمه، ترجمهٔ خدمت/تخصص/پروفایل، ACL تازه پس از cache، رد DST نامعتبر و تطبیق مثبت با ظرفیت واقعی.
- `npx playwright test -c playwright.discovery.config.ts`: هر دو آزمون دسکتاپ و موبایل موفق (۲٫۷ دقیقه)، متصل به برنامهٔ نصب‌شده روی VPS با تونل SSH؛ ورود مدیر، ۱۴۷ زبان، ویرایش/بازبینی/انتشار ترجمه، نمایش فوری فرانسوی، RTL عربی، نبود overflow و خطای JavaScript، و صفر تخلف Axe در WCAG 2 A/AA بخش مدیریت ترجمه.
- مرورگر عمومی دمو: مسیرهای فارسی، انگلیسی، عربی و فرانسوی HTTP 200 و جهت صحیح داشتند.
- نصب نهایی: `https://srun.ir/vianoor/api/version` نسخهٔ `V10.0.0` و مرحلهٔ ۱۰ را برگرداند؛ سرویس‌های نصب‌شده healthy شدند.

گزارش‌های خام آزمون در `.cache/stage10-evidence/` نگه‌داری شده‌اند و به علت استفاده از محیط آزمایش در Git قرار نمی‌گیرند.

 آزمون پذیرش از داده‌ها و حساب‌های مصنوعیِ محیط قبلی آزمایش استفاده می‌کند؛ هیچ حساب واقعی وارد fixture یا Git نمی‌شود. برای کاهش مصرف حافظه، `acceptance-server.mjs` فقط فرایند OS را مشترک می‌کند؛ هر سرویس همچنان HTTP و دیتابیس/Pool مستقل خود را دارد. نمایهٔ تست پیشوند مستقل دارد.

AI، مترجم صوتی/زنده و ML فعال نشده‌اند. صف وضعیت `WAITING_FOR_PROVIDER` دارد و قرارداد provider بدون پیاده‌سازی شبکه است. قرارداد فنی provenance نسخهٔ ۱، ارجاع اصل متن، hash، زبان‌ها، نسخهٔ ترجمه و رضایت را تعریف می‌کند؛ هنوز محتوای گفت‌وگو جمع‌آوری نمی‌شود.

مرجع تحلیلگرها: [مستندات رسمی OpenSearch](https://docs.opensearch.org/latest/analyzers/language-analyzers/index/).
