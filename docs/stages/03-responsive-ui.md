# مرحلهٔ ۳ — رابط دو زبانه و واکنش‌گرا

این مرحله ظاهر محصول و تعامل‌های نمایشی را پیاده می‌کند؛ ورود، مجوز نقش‌ها، رزرو، پرداخت، ارسال پیام، تماس یا اتصال AI عملیاتی نشده‌اند. همهٔ ارقام و اسامی، دادهٔ نمونه‌اند. هیچ اطلاعاتی از مرورگر به سرویس کسب‌وکار ارسال نمی‌شود. آدرس‌های پیش‌نمایش عمومی هستند و نباید در آینده جای کنترل دسترسی API را بگیرند.

## ظاهر و دارایی‌ها

- خانوادهٔ **Vazir 30.1.0 (وزیر)** مطابق درخواست کاربر، محلی از npm؛ فارسی RTL و انگلیسی LTR.
- آیکون‌های واقعی **Font Awesome Free Solid 7.0.1** به صورت SVG؛ بدون CDN یا Kit خارجی.
- پالت یشمی، طلایی ملایم و زمینهٔ روشن با طرح کتاب و نقوش هندسی در صفحهٔ اول؛ دارایی‌ها با CSS/SVG ساخته شده‌اند.
- پروفایل‌ها نمونه و با حروف اول نام هستند؛ تصویر افراد واقعی یا ادعای تأیید تخصص در دادهٔ نمایشی وجود ندارد.
- طراحی از عرض 320px تا دسکتاپ؛ کارت‌های موبایل، منوی جانبی جمع‌شونده، نوار پایین داشبورد، فوکوس واضح، reduced motion و پنجرهٔ جزئیات با بازگشت فوکوس.

## دیدن همهٔ داشبوردها از برنامهٔ وب

`/fa/dashboards` یا `/en/dashboards` گالری تمام ۱۲ محیط است. برای نصب با basePath، پیشوند تنظیم‌شده به مسیرها اضافه می‌شود. وب و admin مستقل‌اند؛ پیش‌نمایش وب امکان مرور همهٔ نقش‌ها را بدون راه‌اندازی admin می‌دهد.

| نقش            | پیش‌نمایش وب               | مسیر اصلی برنامه          |
| -------------- | -------------------------- | ------------------------- |
| مراجعه‌کننده   | `/fa/preview/account`      | web: `/fa/account`        |
| استاد و مشاور  | `/fa/preview/expert`       | web: `/fa/expert`         |
| پاسخ‌گو        | `/fa/preview/responder`    | web: `/fa/responder`      |
| ناظر علمی      | `/fa/preview/scientific`   | admin: `/fa/scientific`   |
| پشتیبانی       | `/fa/preview/support`      | admin: `/fa/support`      |
| مالی           | `/fa/preview/finance`      | admin: `/fa/finance`      |
| محتوا و رویداد | `/fa/preview/content`      | admin: `/fa/content`      |
| سازمان         | `/fa/preview/organization` | admin: `/fa/organization` |
| مدیریت کل      | `/fa/preview/admin`        | admin: `/fa/admin`        |
| هوش مصنوعی     | `/fa/preview/ai`           | admin: `/fa/admin/ai`     |
| مرکز تماس      | `/fa/preview/call-center`  | admin: `/fa/call-center`  |
| عملیات         | `/fa/preview/operations`   | admin: `/fa/operations`   |

همهٔ مسیرها معادل انگلیسی با `/en` دارند. هر پیش‌نمایش چهار زیرصفحهٔ activity، calendar، messages و settings دارد. مسیرهای ثابت ثبت‌شده در کاتالوگ نیز پوستهٔ نمایشی دارند؛ جزئیات دامنه با شناسهٔ واقعی هنوز ساخته نشده‌اند و اسلاگ‌های ناشناخته 404 می‌دهند.

## صفحات عمومی

صفحهٔ اول، درباره، نحوهٔ کار، خدمات و نمونهٔ جزئیات خدمت، موضوع‌ها، فهرست و پروفایل نمونهٔ اساتید، جست‌وجوی صفحات، راهنما، FAQ، تماس، اطلاعیه، همکاری استاد/سازمان، نمونهٔ سند سیاست، کتابخانه، سؤال و رویداد.

در صفحهٔ سیاست متن حقوقی نهایی جعل نشده و فرم پذیرش وجود ندارد. صفحهٔ تماس نشانی جعلی ندارد. ورود و ثبت‌نام، پیام آماده‌سازی و پیوند پیش‌نمایش دارند؛ فرم جمع‌آوری رمز یا دادهٔ شخصی نمایش داده نمی‌شود. صفحهٔ محتوا و رویداد قالب نمایشی است، نه انتشار واقعی.

## تعامل‌های فعال در پیش‌نمایش

- جست‌وجو و فیلتر فهرست اساتید، حالت بدون نتیجه و پاک کردن فیلتر؛
- تغییر زبان با حفظ مسیر، منوی موبایل و انتخاب محیط کاری؛
- فیلتر و جست‌وجوی ردیف‌ها، پنجرهٔ جزئیات، اعلان نمونه؛
- انتخاب روز تقویم نمونه و بازهٔ نمودار، ذخیرهٔ نمایشی در حافظهٔ صفحه؛
- دریافت JSON گزارش **نمونه** در مرورگر؛ هیچ خروجی دادهٔ واقعی نیست؛
- FAQ با details/summary بومی و کنترل‌های دارای نام دسترس‌پذیر.

اعداد نمودار، وضعیت سرویس و تیکت، تراکنش‌ها، زمان‌های تقویم و مدل‌های AI اتصال واقعی ندارند. تغییرات نمایشی با بارگذاری مجدد پاک می‌شوند. نمودارها نمایش آمار واقعی یا نتیجهٔ آزمون مرحلهٔ ۲ نیستند.

## اجرا و زیرمسیر

```bash
npm ci
npm run build:packages
npm run dev:web
# در ترمینال دیگر، در صورت نیاز:
npm run dev:admin
```

برای build در زیرمسیر دلخواه، `NEXT_PUBLIC_BASE_PATH` باید **هنگام build و start یکسان** باشد؛ مقدار بدون اسلش پایانی، مانند `/vianoor`:

```bash
NEXT_PUBLIC_BASE_PATH=/vianoor npm run build --workspace @vianoor/web
NEXT_PUBLIC_BASE_PATH=/vianoor npm run start --workspace @vianoor/web
```

Dockerfile عمومی وب نیز آماده است:

```bash
docker build -f infra/web.Dockerfile \
  --build-arg NEXT_PUBLIC_BASE_PATH=/vianoor \
  -t vianoor-web:stage3 .
```

این راهنما کانتینر یا Nginx سرور شخصی را تغییر نمی‌دهد. دستور جایگزینی نسخهٔ نصب‌شده باید با توجه به پورت و کانتینر فعلی جدا اجرا شود. تنظیمات SSH، دامنه و کلیدها وارد مخزن نشده‌اند.

## آزمون

`npm run check` و `npm run smoke` دروازهٔ عمومی هستند. `npm run test:ui` با build وب و Chromium نصب‌شده اجرا می‌شود. workflow **Responsive UI** زیرمسیر را نیز فعال می‌کند و در عرض‌های 1440 و 390، دو زبان و هر ۱۲ نقش را می‌آزماید: نبود اسکرول افقی، کنترل‌های تعاملی، زبان، دیالوگ، منو، فونت و axe با قواعد WCAG 2 A/AA. تصاویر تمام صفحات اصلی و داشبوردها در artifact `ui-screenshots-and-report` قرار می‌گیرند.

آزمون خودکار، گواهی کامل دسترس‌پذیری یا بررسی انسانی تمام صفحات نیست. مسیرهای پویا فقط اسلاگ‌های نمونهٔ تعریف‌شده را دارند. اتصال به backend در مرحلهٔ مربوط به هر قابلیت انجام می‌شود.
