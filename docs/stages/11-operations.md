# راهنمای مالی مرحله ۱۱

دامنه یکپارچه: [11-scope.md](11-scope.md). شواهد: [stage-11.md](../testing/stage-11.md).

پنج سرویس مستقل payment، wallet، accounting، payout و dispute فقط دیتابیس خود را می‌خوانند و از API داخلی احرازهویت‌شده استفاده می‌کنند.

## تنظیم مدیر

نشانی مدیریت: `/vianoor/fa/admin/finance`. در بخش درگاه‌ها، ارائه‌دهنده، TEST یا LIVE، ارزها و اطلاعات اتصال را ذخیره کنید. هر تغییر نسخه جدید غیرفعال می‌سازد؛ ابتدا آزمون اتصال و سپس فعال‌سازی انجام شود. فیلدهای رمز بعد از ذخیره خالی‌اند؛ خالی گذاشتن در ویرایش مقدار قبلی را حفظ می‌کند. webhook همان نسخه را در پنل ارائه‌دهنده ثبت کنید.

- Stripe: Secret key و Webhook signing secret. کارت و Visa/Mastercard و Apple Pay/Google Pay در Checkout میزبانی‌شده انجام می‌شوند؛ نمایش کیف پول وابسته به حساب، کشور، دستگاه و تنظیمات Stripe است.
- PayPal: Client ID، Client secret و Webhook ID. Orders/Capture، Refund و Payouts پیاده شده‌اند. مجوز Payouts در حساب تجاری لازم است.
- NOWPayments: API key و IPN secret؛ برای برداشت، ایمیل و رمز Payout. کد دومرحله‌ای در ردیف برداشت دریافت و ذخیره نمی‌شود. شبکه‌ها: USDT TRC20/ERC20/BSC/Polygon، USDC Ethereum/Polygon، BTC و ETH.

امضای webhook و سپس مبلغ، ارز و وضعیت ارائه‌دهنده بررسی می‌شود. بازگشت مرورگر کافی نیست. درگاه بدون اطلاعات پذیرندگی غیرفعال می‌ماند؛ کلیدهای شبیه‌ساز به دیتابیس دمو منتقل نمی‌شوند.

## عملیات

مبالغ رشته عدد صحیح در کوچک‌ترین واحد ارزند: IRR/IRT صفر، ارزهای معمول دو، USDT/USDC شش، BTC هشت و ETH هجده رقم اعشار. نرخ تبدیل نسبت صحیح و snapshot منقضی‌شونده است. تراز هر ارز جدا و دفترکل نهایی با trigger تغییرناپذیر است.

پرداخت رزرو درآمد را در موجودی در انتظار استاد می‌گذارد؛ پس از اتمام جلسه و مهلت آزادسازی، کمیسیون و مالیات تنظیم‌شده کسر و درآمد آزاد می‌شود. اختلاف باز یا بررسی ریسک آزادسازی را متوقف می‌کند. مبلغ از مالک رزرو می‌آید. پرداخت دیررس رزرو منقضی را احیا نمی‌کند و به کیف پول مشتری برمی‌گردد.

بازپرداخت منابع را قفل می‌کند و تکرار، سند جدید نمی‌سازد. Stripe/PayPal بازپرداخت به مبدأ دارند. رمزارز ابتدا به کیف پول داخلی و سپس از برداشت تأییدشده بازمی‌گردد؛ endpoint ساختگی برای Refund مستقیم NOWPayments وجود ندارد. کاربران عادی هم مقصد برداشت خود را ثبت می‌کنند.

برداشت بانکی پس از انتقال خارج سامانه با رسید مدیر تکمیل می‌شود؛ اتصال خودکار بانکی ادعا نمی‌شود. PayPal و رمزارز API دارند. نتیجه مبهم، موجودی را قفل نگه می‌دارد. پرداخت رمزارزی مبهم با شناسه بررسی‌شده ارائه‌دهنده قابل تطبیق است. برداشت مبهم بدون شناسه نیازمند بررسی پنل ارائه‌دهنده است؛ ارسال کور دوباره انجام نمی‌شود.

پنل شامل درگاه، پرداخت، دفترکل، بازپرداخت، برداشت، اختلاف، کمیسیون/مالیات، نرخ ارز، ریسک، مغایرت و گزارش روز/ماه/سال است. شماره صورتحساب و خلاصه مبلغ ارائه می‌شود؛ PDF اختصاصی یا سند مالیاتی قانونی پیاده نشده است.

IPinfo اختیاری و نیازمند توکن است؛ نبود آن کشور نامشخص می‌دهد. کشور کارت/صورتحساب و جهش مبلغ کنترل ریسک دارند؛ این کنترل‌ها KYC/AML کامل نیستند. کلیدها، مقصدها و پیام‌های اختلاف با AES-256-GCM و زمینه رکورد رمز می‌شوند و در log نمی‌آیند.

## استقرار

`node scripts/finance/prepare.mjs` روی compose مرحله ۱۰ اعمال می‌شود. `infra/local/finance-key.env` یک بار تولید و حفظ می‌شود؛ پشتیبان امن آن همراه دیتابیس ضروری است و وارد Git نمی‌شود. مهاجرت‌ها افزایشی و در سرویس مالک هستند. شبیه‌ساز فقط در محیط توسعه و loopback مجاز است. بازگشت image به مرحله ۱۰ جایگزین بازیابی تراکنش‌های مالی نیست؛ پیش از rollback پذیرش پرداخت متوقف و snapshot بررسی شود.
