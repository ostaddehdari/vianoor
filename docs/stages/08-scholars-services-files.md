# مرحلهٔ ۸ — اساتید، تخصص‌ها، خدمات و فایل‌ها

شاخه: `stage/08-scholars-services-files`؛ نسخهٔ رابط: `V8.0.0`.
مرجع محدوده: [درخواست کامل](08-scope.md). مرحلهٔ ۷ و قابلیت‌های هوش مصنوعی مرحلهٔ ۱۸ طبق درخواست مالک، پس از مراحل غیرهوش‌مصنوعی اجرا می‌شوند؛ شماره‌های مراحل حفظ شده‌اند.

## پیاده‌سازی

- `scholar-service`: پروندهٔ حرفه‌ای مستقل از حساب، شناسهٔ عمومی موجود، slug یکتا، زبان و سطح، دیدگاه، اطلاعات SEO و نمایش عمومی. ارسال پرونده، بررسی، اصلاح و ارسال مجدد، تأیید با تاریخ اعتبار، تعلیق و رد؛ خودتأییدی مدیر ممنوع است. تغییر اطلاعات تأییدشده نیاز به بررسی مجدد دارد.
- بررسی مستقل مدرک و تخصص، علت قابل مشاهده برای استاد و یادداشت داخلی مدیر، فیلترهای مدیریت و درصد تکمیل/موارد ناقص. شمارهٔ تماس و شماره و فایل مدرک در پاسخ عمومی نیستند. فقط خلاصهٔ انتخاب‌شدهٔ مدرک تأییدشده نمایش داده می‌شود.
- خدمات با نوع، تخصص، دسته، مدت، مبلغ صحیح، ارز، شرایط و تصویر؛ پیش‌نویس، درخواست انتشار، تأیید/رد و غیرفعال‌سازی. تنظیم نیاز به تأیید مدیریت. مبلغ ریال/تومان واحد کامل و USD/EUR واحد خرد است.
- `taxonomy-service`: تخصص و دستهٔ سلسله‌مراتبی، زبان مرکزی، برچسب فارسی/انگلیسی، ترتیب و فعال‌بودن؛ جلوگیری از چرخه و پنهان‌شدن زیرمجموعهٔ والد غیرفعال.
- `file-service`: ذخیرهٔ S3-compatible، اعتبارسنجی پسوند/MIME/signature، قرنطینه و اسکن واقعی ClamAV، پردازش تصویر و حذف metadata. شکست اسکن فایل را منتشر نمی‌کند. API قبلی آواتار حفظ شده و تصویر قدیمی هنگام خواندن مجاز به مخزن مرکزی منتقل می‌شود؛ اصل فایل محلی پاک نمی‌شود.
- مالکیت و ACL در سرویس فایل بررسی می‌شود. بازبین علمی فقط به مدارک متصل به پروندهٔ ارسال‌شده دسترسی دارد؛ دسترسی عمومی به اسناد خصوصی وجود ندارد. لینک ۶۰ثانیه‌ای علاوه بر امضا به نشست/مالک و revision فایل وابسته است؛ قرنطینه لینک قبلی را بی‌اعتبار می‌کند.
- نگهداری ارجاع فایل، جلوگیری از حذف فایل مصرف‌شده و soft delete؛ عملیات حساس در دیتابیس مالک ثبت می‌شود. تجمیع در audit-service مرکزی مربوط به مرحلهٔ بعد است.
- صف پایدار اعلان و یادآوری انقضای مدرک، تحویل idempotent به ایمیل موجود identity؛ متن ایمیل فقط رویداد عمومی و مسیر داشبورد است، نه مدارک یا یادداشت داخلی.

## صفحات و قراردادها

با پیشوند نصب `/vianoor`، مسیرهای `/fa` و `/en` پشتیبانی می‌شوند:

- `/account/professional` برای درخواست استادشدن؛ `/expert/professional` و مسیرهای profile/credentials/offerings/files برای استاد.
- `/admin/experts`، `/admin/expert-applications`، `/admin/verification`، `/admin/expert-documents`، `/admin/services`، `/admin/taxonomy` و `/admin/files`. بازبین علمی مسیرهای مجاز متناظر دارد.
- `/experts` و `/experts/{slug}` برای پروفایل عمومی با canonical و OpenGraph.

زبان‌ها، تخصص‌ها و دیدگاه‌ها داخل فرم حرفه‌ای؛ مدارک، خدمات و تاریخچه در تب‌های همان پرونده قرار دارند. مدیریت تخصص/دسته/زبان در یک صفحه با انتخاب نوع انجام می‌شود.

APIهای جدید زیر `/api/v2/experts`، `/api/v2/taxonomy` و `/api/v2/files/assets` قرار دارند؛ BFF همان احراز هویت کوکی و کنترل Origin قبلی را حفظ می‌کند. دسترسی بین سرویس‌ها فقط API است، نه import دامنه یا دیتابیس مشترک. نقش استادِ حاصل از تأیید صلاحیت به فهرست محیط‌های کاری اضافه می‌شود و دسترسی مراجع باقی می‌ماند.

## اجرای آزمون مستقل

```bash
npm run check
npm run smoke
docker build -f infra/Dockerfile -t vianoor-services:stage8 .
docker build -f infra/web.Dockerfile --build-arg NEXT_PUBLIC_BASE_PATH=/vianoor -t vianoor-web:stage8 .
bash scripts/deploy/stage08-test.sh
```

اسکریپت پروژهٔ مستقل `vianoor-stage8-test` را در `.cache/stage08-test` با کلیدها و دیتابیس‌های مجزا می‌سازد. پورت‌های وب ۱۸۸۸۶، gateway ۱۸۸۸۵ و Mailpit ۱۸۸۸۷ فقط loopback هستند. سرویس‌ها از PostgreSQL، S3 واقعی SeaweedFS و daemon واقعی ClamAV استفاده می‌کنند. تحویل SMTP به Mailpit آزموده می‌شود؛ این آزمون ادعای تحویل به صندوق اینترنتی ندارد.

آزمون بدافزار دو بخش دارد: رشتهٔ استاندارد EICAR با امضاهای واقعی ClamAV؛ و یک PDF بی‌ضرر با امضای hash مخصوص محیط آزمون برای اثبات مسدودشدن چرخهٔ آپلود. امضای آزمایشی فقط با `SCHOLARS_TEST=1` نصب می‌شود.

برای مرورگر، fixture تولیدشدهٔ `infra/qa/scholars-browser.json` را از محیط آزمایشی به `.cache/scholars-browser.json` کپی کنید و پورت loopback وب را تونل کنید، سپس:

```bash
npx playwright test --config playwright.scholars.config.ts
```

fixture صرفاً حساب‌های مصنوعی دارد و در Git/Docker قرار نمی‌گیرد. پس از آزمون می‌توان با `docker compose -f .cache/stage08-test/infra/identity.compose.json stop` منابع محیط آزمایشی را آزاد کرد؛ volumeها نگه داشته می‌شوند.

## مرزهای این تحویل

- رزرو، تقویم، پرداخت، تسویه، تماس/LiveKit، امتیاز و نظر کاربران و کمیسیون طبق محدوده اجرا نشده‌اند.
- انواع فایل این مرحله PDF، JPEG، PNG و WebP هستند. ویدئو نیازمند جریان رسانهٔ مرحلهٔ مربوط است. محدودیت پیش‌فرض آواتار ۵، تصویر ۱۰ و مدرک ۲۰ مگابایت است؛ تنظیمات مدیر سقف ۲۰ مگابایت دارد چون انتقال فعلی JSON/base64 است.
- حذف فایل soft delete است؛ پاک‌سازی فیزیکی دوره‌ای اشیاء و سیاست retention نیاز به تصمیم عملیاتی دارد. ارجاع تصویر جایگزین‌شده و رزرو ارجاع در عملیات ناموفق محافظه‌کارانه حفظ می‌شوند تا فایل اشتباهاً پاک نشود؛ حذف خودکار این ارجاع‌ها در این تحویل نیست.
- فهرست فایل/پرونده API دارای offset است؛ رابط فعلی اولین صفحه را نشان می‌دهد. صف خدمات تا ۱۰۰ مورد نمایش می‌دهد.
- آزمون مستقل، نصب اصلی را تغییر نمی‌دهد. پس از درخواست صریح مالک، نصب عملیاتی جداگانه انجام شد؛ شواهد آن در بخش «نصب عملیاتی» آمده است. پشتیبان دوره‌ای دیتابیس و object storage و پایش ظرفیت دیسک باید در نگهداری سرور لحاظ شوند.

## شواهد

در ۲۰۲۶-۰۹-۲۷:

- `npm run check` موفق: مرز معماری، lint، آزمون واحد، ساخت ۳۲ سرویس و دو برنامه و TypeScript. پس از افزودن آزمون تطابق ترجمه‌ها و حفاظت تصویر دسته‌بندی، lint، هر ۳۶ آزمون واحد و ساخت دو سرویس تغییریافته دوباره موفق شدند.
- `npm run smoke` موفق: ۳۲ scaffold با تفکیک liveness/readiness و هر دو برنامه در فارسی/انگلیسی. این smoke به‌تنهایی اتصال دامنه را اثبات نمی‌کند.
- `tests/integration/scholars.test.ts` روی کد `19f7a36` موفق (۱ سناریوی جامع، حدود ۱۷ ثانیه): ثبت/تأیید ایمیل واقعی از SMTP آزمایشی، کنترل مجوز، منع خودتأییدی، مدرک خصوصی، S3 و ClamAV، اصلاح/ارسال مجدد، بررسی مستقل تخصص/مدرک، تأیید، نقش استاد، انتشار خدمت، محرمانگی پاسخ عمومی، اعلان ایمیلی، تعلیق، قرنطینه و اسکن مجدد، مالکیت و جلوگیری از حذف تصویر دسته‌بندیِ مصرف‌شده.
- Playwright روی Chromium واقعی: دسکتاپ ۱۴۴۰×۱۰۰۰ موفق (حدود ۲٫۸ دقیقه) و موبایل ۳۹۰×۸۴۴ موفق (حدود ۲٫۳ دقیقه). ورود مدیر/استاد، انتخاب محیط کاری، بررسی پرونده، ایجاد و انتشار خدمت، canonical پروفایل عمومی و عدم افشای شمارهٔ مدرک بررسی شدند. فرم فارسی و صفحهٔ عمومی overflow افقی نداشتند؛ Axe در محدودهٔ فرم حرفه‌ای هیچ نقض WCAG2A/AA گزارش نکرد. تصاویر خروجی نیز بازبینی شدند.
- مهلت مرورگر برای اتصال SSH آزمایشی ۶۰ ثانیه است. در تشخیص بارگذاری، درخواست‌های taxonomy و پروندهٔ استاد پاسخ ۲۰۰ داشتند؛ مهلت اولیهٔ ۳۰ ثانیه در یک اجرا کافی نبود.
- پیش از درخواست نصب عملیاتی، نسخهٔ آزمایشی از `/vianoor/api/version` مقدار `V8.0.0 / stage 8` و نصب اصلی مقدار `V6.0.1 / stage 6` برگرداند.

لاگ‌های محلی در `.cache/stage08-final-check.log`، `.cache/stage08-final-smoke.log` و `.cache/stage08-evidence` نگهداری می‌شوند و وارد Git نمی‌شوند. کد آزمون و دستورات اجرای مجدد در مخزن هستند.

## نصب عملیاتی

در ۲۰۲۶-۰۹-۲۷، پس از درخواست صریح نصب `V8.0.0`، اسکریپت `scripts/deploy/stage08.sh` از checkout تمیز `/opt/vianoor-stage08` اجرا شد. پیش از مهاجرت، dump فشردهٔ PostgreSQL، تنظیمات و آواتارها در مسیر خصوصی `/root/vianoor-backups/stage08-*` پشتیبان‌گیری شدند. همان پروژهٔ Compose `vianoor-stage4`، volumeها، حساب‌ها و تنظیمات SMTP قبلی حفظ شدند.

سرویس‌های اصلی با تصاویر آزموده‌شدهٔ مرحلهٔ ۸ فعال شدند؛ scholar، taxonomy، object-storage و scanner نیز به نصب اصلی افزوده شدند. امضای مخصوص آزمون ClamAV در نصب اصلی وجود ندارد. اسکریپت در شکست فعال‌سازی، سرویس‌های قبلی را بازمی‌گرداند و دیتابیس/اشیاء را حذف یا restore نمی‌کند.

آدرس عمومی `https://srun.ir/vianoor/api/version` مقدار `{"version":"V8.0.0","stage":8}` برگرداند. نوشتن/خواندن/حذف یک شیء مصنوعی موقت در مخزن عملیاتی و اسکن آن با ClamAV موفق بود؛ آماده‌بودن SMTP نیز تأیید شد. این بررسی ایمیلی برای کاربران ارسال نکرد. آزمون جامع پرونده و انتشار خدمت همچنان در محیط مستقل انجام شده است تا دادهٔ مصنوعی وارد حساب‌های اصلی نشود.

بررسی Chromium روی دامنهٔ اصلی در دسکتاپ ۱۴۴۰×۱۰۰۰ و موبایل ۳۹۰×۸۴۴ موفق شد: صفحهٔ ورود و فهرست اساتید فارسی/انگلیسی پاسخ ۲۰۰، جهت صحیح، بدون overflow افقی و خطای JavaScript؛ endpoint خصوصی بدون نشست پاسخ ۴۰۱ داد. همهٔ سرویس‌های دارای healthcheck سالم بودند و تصاویر صفحات بازبینی شدند.

ورود: `https://srun.ir/vianoor/fa/auth/login`؛ فرم حرفه‌ای: `/vianoor/fa/account/professional`؛ مدیریت: `/vianoor/fa/admin/experts`؛ فهرست عمومی: `/vianoor/fa/experts`. مسیرهای مدیریت نیازمند حساب با مجوز مربوط هستند و فهرست عمومی تا زمان تأیید و انتشار استاد واقعی می‌تواند خالی باشد.
