# شواهد مرحله ۱۱

محیط آزمون: کانتینر خصوصی `vianoor-stage11-dev` روی VPS، زیرساخت مجزای `vianoor-stage9-test`، دیتابیس مستقل برای هر مالک. اطلاعات حساب‌ها مصنوعی و خارج Git نگهداری می‌شوند.

## آزمون واقعی داخلی

`FINANCE_TEST=1 node --import tsx --test tests/integration/finance.test.ts` پس از اجرای `scripts/finance/acceptance-server.mjs`:

- ۱۰۰ webhook امضاشده تکراری: یک پرداخت و یک سند دفترکل؛ امضای نامعتبر رد می‌شود.
- ۱۰۰ درخواست هم‌زمان پرداخت یک رزرو: یک موفقیت و ۹۹ BOOKING_ALREADY_PAID.
- ۱۰۰۰ تراکنش واقعی PostgreSQL: تراز هر ارز برابر و موجودی نهایی صحیح.
- رزرو پولی با تأیید رایگان دور زده نمی‌شود؛ پرداخت دیررس فقط کیف پول را بستانکار می‌کند.
- پرداخت ناقص و منقضی رمزارزی تا تأیید نهایی موجودی ایجاد نمی‌کنند.
- بازپرداخت، آزادسازی پس از جلسه، توقف آزادسازی در اختلاف، پیام اختلاف، تبدیل ارز و تکرار درخواست‌ها.
- کنترل دسترسی مدیر، عدم برگشت کلیدها، رمزگذاری مقصد برداشت و تغییرناپذیری دفترکل.

آزمون پایان جلسه با جلو بردن مصنوعی زمان پایان در دیتابیس **مجزای آزمون** انجام می‌شود. تست روی داده واقعی مراجعه‌کنندگان اجرا نمی‌شود.

## مرز شبیه‌سازی

HTTP سرویس‌های داخلی، تراکنش‌ها، قفل‌ها و دفترکل واقعی‌اند. سمت بیرونی Stripe/PayPal/NOWPayments توسط `provider-fixture.mjs` روی loopback شبیه‌سازی می‌شود. این آزمون، موفقیت پرداخت واقعی یا تأیید حساب پذیرندگی را ثابت نمی‌کند. دریافت پول زنده، شرایط کشوری، نمایش Apple Pay/Google Pay و مجوز Payout پس از ورود اطلاعات حساب توسط مدیر نیازمند آزمون پذیرندگی هستند.

`tests/finance.test.ts` دقت واحد پول، تراز چندارزی، رمزگذاری/AAD، امضای Stripe و canonical IPN را بررسی می‌کند. نتیجه ساخت کامل، smoke و مرورگر پس از اجرای نهایی در همین سند ثبت می‌شود.

## نتیجه اجرای نهایی — ۲۰۲۶/۰۹/۲۸

- `npm run check`: موفق؛ کنترل معماری ۳۲ سرویس، lint، ۵۳ آزمون واحد، ساخت سرویس‌ها و هر دو برنامه، typecheck.
- `npm run smoke`: موفق؛ ۳۲ entrypoint در حالت بدون زیرساخت آماده‌نبودن را درست اعلام کردند و مسیر/جهت فارسی و انگلیسی هر دو برنامه بررسی شد. سلامت واقعی سرویس‌های مالی جداگانه روی PostgreSQL سرور تأیید شد.
- آزمون پذیرش مالی: موفق؛ موارد بالا به‌علاوه ۲۰ درخواست هم‌زمان با کلید یکسان (یک پرداخت)، برداشت بانکی مشتری با رسید مدیر، و برداشت رمزارزی با تأیید دومرحله‌ای شبیه‌ساز.
- `FINANCE_TEST=1 node scripts/finance/browser-acceptance.mjs`: موفق؛ ورود واقعی، تمام تب‌های مدیریت، خالی ماندن رمزهای ذخیره‌شده در فرم، متن فارسی/انگلیسی، RTL/LTR، نمایش کیف پول و برداشت روی موبایل، بدون سرریز افقی یا خطای JavaScript. axe برای پنل مدیریت با قواعد WCAG2 A/AA بدون تخلف بود.
- وب برای استقرار با `NEXT_PUBLIC_BASE_PATH=/vianoor` ساخته شد؛ اسکریپت بسته‌بندی این مقدار را کنترل می‌کند. کل کانتینر آزمون image نمی‌شود؛ فقط source و خروجی‌های مشخص build بسته‌بندی می‌شوند.
- دمو در `/opt/vianoor-stage11` با V11.0.0 نصب شد. compose همان پروژه `vianoor-stage4` و داده‌های پیشین را حفظ می‌کند. پنج سرویس مالی و سایر سرویس‌های فعال healthy شدند. ۱۱۹۰ کلید UI bootstrap شد؛ ترجمه‌های ویرایش‌شده حفظ شدند.
- پیش از استقرار، دیتابیس و تنظیمات خصوصی پشتیبان گرفته شد؛ مسیر ثبت‌شده سرور `/opt/vianoor-backups/stage11-20260927T204326Z` است. هیچ درگاه شبیه‌سازی‌شده‌ای در دیتابیس نصب عمومی ایجاد نشده است.

اسکرین‌شات‌ها و خروجی خام آزمون‌ها در `.cache/stage11-evidence` محلی نگهداری می‌شوند و به Git اضافه نمی‌شوند؛ fixture ورود نیز خصوصی و خارج Git است.
